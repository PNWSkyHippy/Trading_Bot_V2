# ADAPTIVE_REGIME_TUNING_PATCH_BRIEF.md

## Objective
Improve `adaptive_regime` backtest observability so we can evaluate:
- trend mode vs mean reversion mode
- long side vs short side
- exit reason behavior
- low-sample false positives
- symbol-specific suitability

Do **not** redesign the strategy yet.
Do **not** change entry/exit thresholds yet.
This patch is for **granular reporting and filtering only**.

---

## Current problem

The current backtest output aggregates all `adaptive_regime` trades together, which hides the most important questions:

1. Is **trend mode** carrying the strategy?
2. Is **mean_rev mode** dragging performance down?
3. Are **longs** better than **shorts**?
4. Are exits working as intended?
5. Are "good" symbols just low-sample noise (2-4 trades)?

Right now we only see total symbol-level PnL / WR / PF, which is not enough to tune the strategy intelligently.

---

## Evidence from latest run

Command used:
```powershell
python intelligence/backtester.py --all --strategy adaptive_regime --days 365 --tf 1h --asset-class stock --stop two_bar
Observed:

mixed symbol performance
some strong names: TSLA, TXN, AMAT, LRCX, NVDA
many weak names: META, MSFT, KLAC, ALAB, INTC
tiny total returns overall
several "good" outcomes are based on very small sample sizes (2-4 trades)
current report label bug: Stop Mode: 2-Bar Trailing (N=bar) should show actual integer lookback
Conclusion: We need mode-level and side-level decomposition before changing strategy thresholds.

Required patch scope
1. Extend BacktestTrade with adaptive metadata fields
In intelligence/backtester.py, extend BacktestTrade to include optional fields:

entry_mode: str = "" # "trend" or "mean_rev"
regime: str = ""
entry_rsi: float = 0.0
entry_adx: float = 0.0
entry_atr: float = 0.0
entry_timeframe: str = ""
Populate these from trade["entry_metadata"] when the trade closes.

Expected source metadata keys already exist in adaptive_regime.py:

adaptive_exit_mode
regime
rsi
adx
atr
Map:

entry_mode ← adaptive_exit_mode
regime ← regime
entry_rsi ← rsi
entry_adx ← adx
entry_atr ← atr
entry_timeframe ← timeframe passed into simulation
This must not break other strategies; default blank/zero values are fine for all non-adaptive trades.

2. Add backtest filtering options for mode and side
Add optional CLI args in intelligence/backtester.py:

parser.add_argument("--mode", default="all", choices=["all", "trend", "mean_rev"])
parser.add_argument("--side", default="all", choices=["all", "long", "short"])
These should only affect trade entry acceptance during simulation, not data fetching.

Logic:

if --mode trend, only allow entries whose signal.metadata["adaptive_exit_mode"] == "trend"
if --mode mean_rev, only allow entries whose signal.metadata["adaptive_exit_mode"] == "mean_rev"
if --side long, only allow long entries
if --side short, only allow short entries
This should work for any strategy, but mode filtering will only be meaningful for adaptive_regime. For non-adaptive strategies, mode filter can simply ignore entries unless mode == "all"`.

Pass these args through:

run()
run_strategy()
run_all()
_simulate()
Suggested new params:

entry_mode_filter: str = "all"
entry_side_filter: str = "all"

Mode breakdown

mean_rev wins/losses
mean_rev win rate
mean_rev total pnl
mean_rev avg pnl_pct
Side breakdown
long trades / WR / PF / total pnl
short trades / WR / PF / total pnl
Exit reason breakdown
Print counts by exit reason:

stop_loss
take_profit
adaptive_ema_cross_exit
adaptive_bb_midline_exit
adaptive_rsi_exit
backtest_end
Also print total pnl by exit reason if easy.

This should appear below the normal report block, not replace it.

4. Add aggregate adaptive summary to print_portfolio_summary()
When --all --strategy adaptive_regime is run, append a special section:

Aggregate by mode
total trend trades
trend WR
trend PF
trend total pnl
total mean_rev trades
mean_rev WR
mean_rev PF
mean_rev total pnl
Aggregate by side
long trades / WR / PF / total pnl
short trades / WR / PF / total pnl
Aggregate by exit reason
exit reason counts
avg pnl by exit reason
Do not use naive PF averages across symbols for this section. Compute from the full combined trade list across all results.

5. Add low-sample warning labels
In both per-symbol report and summary table:

if total trades < 10 → mark LOW SAMPLE
if trend trades < 5 → mark TREND LOW SAMPLE
if mean_rev trades < 5 → mark MEAN_REV LOW SAMPLE
Examples:

NVDA 2 trades → LOW SAMPLE
LRCX 4 trades → LOW SAMPLE
TSLA 4 trades → LOW SAMPLE
Do not treat these as validated "GO" without warning.

7. Fix stop mode label bug
Current output shows: Stop Mode: 2-Bar Trailing (N=bar)

This is wrong.

Fix so it prints the actual lookback integer:

or whatever --lookback value was passed
Implement by storing the actual lookback in BacktestResult, e.g.:

stop_lookback: int = 0
Then print from that field rather than parsing the stop_mode string.
