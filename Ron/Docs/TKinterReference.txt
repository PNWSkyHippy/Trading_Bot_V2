The tkinter.ttk.Frame widget is a native, themed rectangular 
container used primarily to organize, group, and manage the 
layout of other widgets in a graphical user interface.
Basic Syntax
python
import tkinter as tk
from tkinter import ttk

root = tk.Tk()

# Create a themed Frame
frame = ttk.Frame(root, padding=10)
frame.grid(row=0, column=0)
Use code with caution.
Configuration Options
You can customize a ttk.Frame using the following properties:
Option	Description
padding	Space inside the frame border (can be a single integer, 
a 2-tuple (width, height), or a 4-tuple (left, top, right, 
bottom)).
borderwidth	The width of the frame's border frame (e.g., 
borderwidth=2).
relief	Specifies the 3D border style. Options include 'flat' 
(default), 'raised', 'sunken', 'groove', or 'ridge'.
width	The explicit width of the frame in pixels. (Ignored if 
the geometry manager shrinks/expands it to fit child widgets 
unless grid propagation is disabled).
height	The explicit height of the frame in pixels.
cursor	Changes the mouse pointer icon when hovering over the 
frame.
style	Used to link the frame to a specific custom theme/style 
layout.
takefocus	A boolean (True/False) determining if the frame 
can accept keyboard focus via tabbing.
class_	Allows assigning a custom widget class category name to 
the same for bulk styling configurations.
Common Methods
Because ttk.Frame inherits from the core Tkinter widget classes, 
it shares all fundamental geometry and configuration methods:
• frame.grid(**options): Positions the frame using a grid-based 
geometry manager.
• frame.pack(**options): Positions the frame by packing it against 
the parent window edges.
• frame.configure(option=value) or frame['option'] = value: 
Changes options dynamically after initialization.
• frame.winfo_children(): Returns a list of all child widgets 
currently packed/gridded inside this frame.
Quick Example: Object-Oriented Layout
Subclassing ttk.Frame is the recommended way to design clean, 
modular components in Tkinter desktop applications:
python
import tkinter as tk
from tkinter import ttk

class CustomForm(ttk.Frame):
    def __init__(self, parent):
        # Initialize the frame container
        super().__init__(parent, padding="15 15 15 15", 
		relief="groove", borderwidth=2)
        
        # Add widgets directly inside this frame
        self.label = ttk.Label(self, text="Enter Name:")
        self.label.grid(row=0, column=0, padx=5, pady=5)
        
        self.entry = ttk.Entry(self)
        self.entry.grid(row=0, column=1, padx=5, pady=5)

if __name__ == "__main__":
    root = tk.Tk()
    root.title("App window")
    
    # Place our custom frame into the main root window
    form = CustomForm(root)
    form.pack(padx=20, pady=20)
    
    root.mainloop()
Use code with caution.

To understand how options like weight affect a ttk.Frame, we have 
to look at the relationship between the Frame itself and the 
Geometry Manager (like .grid()) controlling it.
The weight parameter is not actually an option of the ttk.Frame 
widget itself. Instead, it is an option of the grid row and 
column configuration (grid_rowconfigure and grid_columnconfigure). 
It dictates how extra space in the window is distributed when 
the user resizes it.
Here is a breakdown of how layout options, sizing, and weight 
interact with a ttk.Frame.
How weight Affects Frames & Layouts
By default, rows and columns have a weight of 0. This means if 
you expand the main window, the widgets and frames stay glued 
to their original small size, leaving empty background space 
around them.
Giving a row or column a weight of 1 (or higher) tells Tkinter: 
"This row/column should absorb any extra space when the window 
grows."
1. Making a Frame Expand to Fill the Window
If you put a ttk.Frame inside your main root window, the frame 
won't automatically stretch just because you resized the window. 
You must configure the root window's grid columns/rows to have 
weight, and tell the frame to stick to all edges using 
sticky="nsew".
python
root = tk.Tk()

# Tell the root window to give all extra space to column 0 and 
row 0
root.columnconfigure(0, weight=1)
root.rowconfigure(0, weight=1)

# Create the frame and tell it to stretch to North, South, East, 
and West
frame = ttk.Frame(root, relief="sunken", borderwidth=2)
frame.grid(row=0, column=0, sticky="nsew") 
Use code with caution.
2. Proportional Scaling (Weight Ratios)
If you have multiple columns or frames inside a frame, you can 
use different weights to distribute space proportionally:
• Column 0 (weight=1) and Column 1 (weight=1): They will grow 
at the exact same rate, splitting extra space 50/50.
• Column 0 (weight=1) and Column 1 (weight=2): Column 1 will get 
twice as much of the newly created space as Column 0 when the 
window expands.

Common Layout Patterns using Weight 0 and 1
1. The Persistent Sidebar (Horizontal Splitting)
Think of an email client or a code editor. You want the left 
sidebar to stay a fixed width, while the main content area expands 
to fill your screen.
• Column 0 (Sidebar Frame): weight=0. Stays exactly the width 
you design it.
• Column 1 (Main Content Frame): weight=1. Stays tiny until you 
resize the window, then it grows to take over the screen.
2. The Fixed Header/Footer (Vertical Splitting)
Think of a webpage or a modern app with a top menu bar or a 
bottom status bar.
• Row 0 (Header Frame): weight=0. Stays a slim banner at the top.
• Row 1 (Body Content Frame): weight=1. Expands vertically to 
fill the rest of the window.

It is helpful to remember that weight and sticky do two different

2. sticky grows the widget inside that cell: If a grid cell 
expands to 500 pixels wide, but your frame inside it doesn't 
have sticky="ew", the frame will stay its original size and 
just sit quietly in the center of that newly expanded 500-pixel 
slot.

One Watch-out: The sticky Option
Since you mentioned your weight=1 frame grows in both directions 
(ns and ew), it means you successfully applied sticky="nsew".
It is helpful to remember that weight and sticky do two different 
jobs:
1. weight grows the grid cell (the invisible slot): It tells 
the grid row/column itself to get bigger.
2. sticky grows the widget inside that cell: If a grid cell 
expands to 500 pixels wide, but your frame inside it doesn't 
have sticky="ew", the frame will stay its original size and just 
sit quietly in the center of that newly expanded 500-pixel slot.

The sticky option in .grid() controls alignment and stretching. 
It tells Tkinter exactly which walls of its invisible grid cell 
the widget should "stick" to.
If a grid cell is larger than the widget inside it (usually 
because a row or column grew due to its weight), sticky decides 
whether the widget stretches to fill that space or stays small 
and hugs a specific side.
Think of it like anchor points or magnetic walls using compass 
directions (North, South, East, West).

Directional Breakdown: What Each Setting Does
1. Single Directions (Alignment / No Stretching)
If you only provide one or two adjacent letters, the widget 
remains its default size (shrink-wrapped around its content) 
and simply glues itself to that side or corner of the cell.
• sticky="n" (North): Centers the widget horizontally and glues 
it to the top edge.
• sticky="s" (South): Centers the widget horizontally and glues 
it to the bottom edge.
• sticky="e" (East): Centers the widget vertically and glues it 
to the right edge.
• sticky="w" (West): Centers the widget vertically and glues it 
to the left edge.
• sticky="ne" (North-East): Glues the widget perfectly into the 
top-right corner.
2. Opposite Directions (Stretching in One Axis)
When you pair opposite directions, you pull the widget toward 
opposing walls simultaneously. This forces the widget to stretch 
to bridge the gap, but only in that specific direction.
• sticky="ns" (North-South):
	• What it does: Stretches the widget vertically from the 
very top to the very bottom of the cell.
	• Horizontal behavior: It does not stretch horizontally. 
It stays its natural width and remains centered left-to-right.
	• Real-world use: A vertical scrollbar or a tall divider 
line.
• sticky="ew" (East-West):
	• What it does: Stretches the widget horizontally from 
the far left to the far right of the cell.
	• Vertical behavior: It does not stretch vertically. It 
stays its natural height and remains centered top-to-bottom.
	• Real-world use: A text input field (Entry) or a button 
that spans the full width of a form.
3. All Directions (Full Stretching)
• sticky="nsew" (or "nswe"—the letter order doesn't matter):
	• What it does: Stretches the widget in both directions 
completely filling the grid cell like liquid filling a box.
	• Real-world use: Standard practice for ttk.Frame 
containers so they completely mask the root window behind them 
and scale perfectly during a resize.
Quick Visual Reference
Imagine a widget inside a large grid cell:
Sticky Setting	Visual Result
None (Default)	Stays small. Sits dead center in the middle of 
the cell.
"w"	Stays small. Moves to the left wall, centered vertically.
"ew"	Becomes a wide, flat strip stretching left-to-right.
"ns"	Becomes a tall, skinny strip stretching top-to-bottom.
"nsew"	Expands completely to match the exact size of the cell.
