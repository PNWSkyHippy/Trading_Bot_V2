👋 Basics — SQL, MySQL, RDBMS

SQL  MySQL  RDBMS  # what you are talking to
SQL is the standard language for relational databases: insert, search, update and delete records
MySQL is a free, open-source RDBMS (first released 1995, owned by Oracle). Runs WordPress, Facebook, Uber, GitHub, YouTube, etc.
Data lives in **tables**: a *column* (field) is vertical and has a type; a *row* (record) is one entry
Tables are linked by shared columns (a key in one table points at a key in another) & that is the "relational" part
SELECT * FROM Customers;      -- the shape of nearly every query
A web site showing DB data needs: an RDBMS (MySQL) + a server language (PHP, Python, Node) + SQL + HTML/CSS
statement rules  # case, semicolons, whitespace
SQL keywords are NOT case sensitive: select = SELECT (convention: keywords in UPPER case)
A semicolon ends a statement; required when sending more than one statement in one call
Whitespace and newlines are free & break long queries over several lines
Text/date values go in single quotes 'Germany'; numbers do not WHERE ID = 1
Table/column name case: on Linux/Mac table names ARE case sensitive; on Windows they are not
the main commands  # cheat list of the verbs
CommandDoes
SELECTextracts data from a database
INSERT INTOinserts new rows
UPDATEmodifies existing rows
DELETEdeletes rows
CREATE DATABASE / DROP DATABASEcreates / deletes a database
CREATE TABLE / ALTER TABLE / DROP TABLEcreates / modifies / deletes a table
CREATE INDEX / DROP INDEXcreates / deletes an index (search key)
-- comment  /* comment */  # comments
Single line: -- & **a space is required after the two dashes** in MySQL (# also works in MySQL)
Multi line: /* ... */; can also hide just part of a statement
-- Selects all German customers
SELECT * FROM Customers
WHERE Country = 'Germany';

SELECT * FROM Customers -- WHERE City='Berlin';   (rest of line ignored)

/* Selects all German customers
   from Berlin */
SELECT CustomerName, /*City,*/ Country FROM Customers;   -- hide one column
--City with no space is NOT a comment in MySQL (it parses as minus minus)

🔍 Querying Data

SELECT  FROM  # pick columns from a table
Result of a query is a **result-set** (a temporary table)
SELECT column1, column2, ...
FROM table_name;

SELECT CustomerName, City, Country FROM Customers;
SELECT * FROM Customers;            -- ALL columns
SELECT * is handy for poking around; name the columns you need in real code
SELECT DISTINCT  # unique values only 
SELECT DISTINCT Country FROM Customers;
SELECT COUNT(DISTINCT Country) FROM Customers;   -- how many unique countries
DISTINCT with several columns de-duplicates the *combination*
WHERE  # filter rows 
SELECT column1, column2
FROM table_name
WHERE condition;

SELECT * FROM Customers WHERE Country = 'Mexico';   -- text in quotes
SELECT * FROM Customers WHERE CustomerID = 1;       -- numbers without
SELECT * FROM Customers WHERE CustomerID > 80;
WHERE is also used by UPDATE and DELETE
OperatorMeaning
=equal
> <greater / less than
>= <=greater / less than or equal
<>not equal (!= also works in MySQL)
BETWEENwithin a range
LIKEpattern search
INone of several values
AND  OR  NOT  # combine conditions
AND & all conditions must be TRUE; OR & any condition TRUE; NOT & reverses a condition
SELECT * FROM Customers WHERE Country = 'Germany' AND City = 'Berlin';
SELECT * FROM Customers WHERE City = 'Berlin' OR City = 'Stuttgart';
SELECT * FROM Customers WHERE NOT Country = 'Germany';

-- combine: use parentheses
SELECT * FROM Customers
WHERE Country = 'Germany' AND (City = 'Berlin' OR City = 'Stuttgart');

SELECT * FROM Customers
WHERE NOT Country = 'Germany' AND NOT Country = 'USA';
NOT pairs with other operators: NOT LIKE, NOT BETWEEN, NOT IN, IS NOT NULL, NOT EXISTS
SELECT * FROM Customers WHERE CustomerName NOT LIKE 'A%';
SELECT * FROM Customers WHERE CustomerID NOT BETWEEN 10 AND 60;
SELECT * FROM Customers WHERE City NOT IN ('Paris', 'London');
SELECT * FROM Customers WHERE NOT CustomerID > 50;     -- same as <= 50
AND binds tighter than OR & always parenthesize mixed conditions
ORDER BY  ASC  DESC  # sort the result
Ascending (ASC) is the default
SELECT * FROM Products ORDER BY Price;               -- low to high
SELECT * FROM Products ORDER BY Price DESC;          -- high to low
SELECT * FROM Customers ORDER BY Country, CustomerName;          -- tie-break by 2nd column
SELECT * FROM Customers ORDER BY Country ASC, CustomerName DESC;
ORDER BY goes after WHERE/GROUP BY/HAVING, and before LIMIT
LIMIT  OFFSET  # only the first N rows (paging)
Useful on big tables & returning thousands of rows hurts performance
SELECT * FROM Customers LIMIT 3;                    -- first 3
SELECT * FROM Customers LIMIT 3 OFFSET 3;           -- rows 4-6 (skip 3)
SELECT * FROM Customers WHERE Country='Germany' LIMIT 3;
SELECT * FROM Customers ORDER BY Country LIMIT 3;   -- sort first, then cut

-- top 5 most expensive products
SELECT ProductName, Price FROM Products
ORDER BY Price DESC, ProductID
LIMIT 5;
Short form: LIMIT offset, count & LIMIT 3, 3 is the same as LIMIT 3 OFFSET 3
MySQL uses LIMIT; SQL Server uses SELECT TOP, Oracle uses FETCH FIRST
IS NULL  IS NOT NULL  # testing for missing data
NULL = unknown / missing / inapplicable. It is **not** 0 and **not** ''
Comparison operators (=, <, <>) can NOT test for NULL & use IS NULL / IS NOT NULL
SELECT CustomerName, ContactName, Address
FROM Customers
WHERE Address IS NULL;

SELECT CustomerName, ContactName, Address
FROM Customers
WHERE Address IS NOT NULL;
WHERE Address = NULL never matches anything
LIKE  %  _  # pattern matching with wildcards
% & zero, one or many characters; _ & exactly one character
PatternFinds
LIKE 'a%'starts with a
LIKE '%a'ends with a
LIKE '%or%'contains "or" anywhere
LIKE '_r%'r in the second position
LIKE 'a_%'starts with a, at least 2 chars
LIKE 'a__%'starts with a, at least 3 chars
LIKE 'a%o'starts with a, ends with o
LIKE 'bl%'bl, black, blue, blob
LIKE 'h_t'hot, hat, hit
SELECT * FROM Customers WHERE CustomerName LIKE 'a%';
SELECT * FROM Customers WHERE City LIKE '%es%';
SELECT * FROM Customers WHERE City LIKE '_ondon';       -- London, Condon...
SELECT * FROM Customers WHERE City LIKE 'L_n_on';
SELECT * FROM Customers WHERE CustomerName NOT LIKE 'a%';
MySQL LIKE is case-insensitive with the default collation
Leading % ('%abc') cannot use an index & slow on big tables
IN  NOT IN  # match any value in a list
Shorthand for several ORs
SELECT * FROM Customers WHERE Country IN ('Germany', 'France', 'UK');
SELECT * FROM Customers WHERE Country NOT IN ('Germany', 'France', 'UK');

-- with a subquery
SELECT * FROM Customers
WHERE CustomerID IN (SELECT CustomerID FROM Orders);        -- customers with orders
SELECT * FROM Customers
WHERE CustomerID NOT IN (SELECT CustomerID FROM Orders);    -- customers with none
NOT IN returns nothing if the list/subquery contains a NULL & prefer NOT EXISTS then
BETWEEN  AND  # inclusive range
Works with numbers, text and dates; both ends are **included**
SELECT * FROM Products WHERE Price BETWEEN 10 AND 20;
SELECT * FROM Products WHERE Price NOT BETWEEN 10 AND 20;
SELECT * FROM Products
WHERE ProductName BETWEEN 'Carnarvon Tigers' AND 'Mozzarella di Giovanni'
ORDER BY ProductName;
SELECT * FROM Orders WHERE OrderDate BETWEEN '1996-07-01' AND '1996-07-31';
AS  (aliases)  # temporary names for columns and tables
Alias lives only for the duration of the query; makes names shorter or more readable
SELECT CustomerID AS ID, CustomerName AS Customer FROM Customers;

-- quotes needed when the alias has spaces
SELECT CustomerName AS "My Great Customers" FROM Customers;

-- combine columns
SELECT CustomerName, CONCAT_WS(', ', Address, PostalCode, City, Country) AS Address
FROM Customers;

-- table aliases (shorter joins)
SELECT o.OrderID, c.CustomerName
FROM Customers AS c, Orders AS o
WHERE c.CustomerName = 'Around the Horn' AND c.CustomerID = o.CustomerID;
AS is optional but clearer; an alias is NOT usable in WHERE (it is in ORDER BY / HAVING)
CASE  WHEN  # if / else inside a query
Goes through conditions in order and returns the value of the first one that is true; otherwise the ELSE value (or NULL)
SELECT OrderID, Quantity,
CASE
    WHEN Quantity > 30 THEN 'The quantity is greater than 30'
    WHEN Quantity = 30 THEN 'The quantity is 30'
    ELSE 'The quantity is under 30'
END AS QuantityText
FROM OrderDetails;

-- in ORDER BY
SELECT CustomerName, City, Country FROM Customers
ORDER BY (CASE WHEN City IS NULL THEN Country ELSE City END);
IFNULL  COALESCE  # replace NULLs
Math with NULL gives NULL: Price * (InStock + InOrder) is NULL if InOrder is NULL
COALESCE(val1, val2, ..., val_n)    -- first non-NULL value (the standard way)
IFNULL(expr, alt)                    -- MySQL-only two-argument version

SELECT ProductName, Price * (InStock + COALESCE(InOrder, 0)) FROM Products;
SELECT ProductName, Price * (InStock + IFNULL(InOrder, 0))   FROM Products;
Also: NULLIF(a, b) returns NULL if equal; IF(cond, yes, no); ISNULL(x) returns 1/0

📊 Aggregates & Grouping

COUNT()  # number of rows 
SELECT COUNT(*) FROM Products;                      -- all rows
SELECT COUNT(ProductName) FROM Products;            -- rows where the column is not NULL
SELECT COUNT(DISTINCT Country) FROM Customers;      -- unique values
SELECT COUNT(*) FROM Products WHERE Price > 20;
COUNT(col) skips NULLs; COUNT(*) counts every row
SUM()  # total of a numeric column 
SELECT SUM(Quantity) FROM OrderDetails;
SELECT SUM(Quantity) FROM OrderDetails WHERE ProductId = 11;
SELECT SUM(Price * Quantity) AS Total FROM OrderDetails od
JOIN Products p ON od.ProductID = p.ProductID;
NULLs are ignored
AVG()  # average of a numeric column 
SELECT AVG(Price) FROM Products;
SELECT * FROM Products WHERE Price > (SELECT AVG(Price) FROM Products);   -- above average
MIN()  MAX()  # smallest / largest
Work with numbers, strings and dates
SELECT MIN(Price) AS SmallestPrice FROM Products;
SELECT MAX(Price) AS LargestPrice  FROM Products;
SELECT MIN(BirthDate) AS EarliestBirthdate FROM Employees;
SELECT MAX(BirthDate) AS LatestBirthdate   FROM Employees;
Result column has no name unless you add AS
GROUP BY  # one summary row per group
Almost always paired with COUNT / SUM / AVG / MIN / MAX
SELECT Country, COUNT(CustomerID) AS "Number of Customers"
FROM Customers
GROUP BY Country;

-- sorted high to low
SELECT Country, COUNT(CustomerID) AS "Number of Customers"
FROM Customers
GROUP BY Country
ORDER BY COUNT(CustomerID) DESC;

-- with a join
SELECT Shippers.ShipperName, COUNT(Orders.OrderID) AS "Number of Orders"
FROM Orders
LEFT JOIN Shippers ON Orders.ShipperID = Shippers.ShipperID
GROUP BY ShipperName;
Every non-aggregated column in SELECT must be in GROUP BY (MySQL's ONLY_FULL_GROUP_BY mode enforces this)
HAVING  # filter the groups
WHERE filters rows **before** grouping; HAVING filters groups **after** aggregation
SELECT Country, COUNT(CustomerID) AS "Number of Customers"
FROM Customers
GROUP BY Country
HAVING COUNT(CustomerID) > 5
ORDER BY COUNT(CustomerID) DESC;

SELECT Employees.LastName, COUNT(Orders.OrderID) AS NumberOfOrders
FROM Orders
INNER JOIN Employees ON Orders.EmployeeID = Employees.EmployeeID
WHERE LastName = 'Davolio' OR LastName = 'Fuller'
GROUP BY LastName
HAVING COUNT(Orders.OrderID) > 25;
Clause order: SELECT & FROM & WHERE & GROUP BY & HAVING & ORDER BY & LIMIT

🔗 Joins & Set Operations

JOIN overview  # combine rows from tables on a related column
JoinReturns
INNER JOINonly rows that match in BOTH tables
LEFT JOINall rows from the left table + matches from the right (NULL if none)
RIGHT JOINall rows from the right table + matches from the left (NULL if none)
CROSS JOINevery row of A paired with every row of B (Cartesian product)
Typical link: a foreign key in one table equals the primary key of another (Orders.CustomerID = Customers.CustomerID)
JOIN alone means INNER JOIN in MySQL
INNER JOIN  # matches in both 
SELECT table1.column1, table2.column1
FROM table1
INNER JOIN table2
ON table1.condition_column = table2.condition_column;

SELECT Products.ProductID, Products.ProductName, Categories.CategoryName
FROM Products
INNER JOIN Categories ON Products.CategoryID = Categories.CategoryID;

-- more than two tables: chain the joins
SELECT Orders.OrderID, Customers.CustomerName, Shippers.ShipperName
FROM Orders
INNER JOIN Customers ON Orders.CustomerID = Customers.CustomerID
INNER JOIN Shippers  ON Orders.ShipperID  = Shippers.ShipperID;
A product with no (or an unknown) CategoryID simply disappears from an inner join
LEFT JOIN  # all of the left table 
SELECT Customers.CustomerName, Orders.OrderID
FROM Customers
LEFT JOIN Orders ON Customers.CustomerID = Orders.CustomerID
ORDER BY Customers.CustomerName;

-- customers who have NOT ordered: filter for the NULL side
SELECT Customers.CustomerName, Orders.OrderID
FROM Customers
LEFT JOIN Orders ON Customers.CustomerID = Orders.CustomerID
WHERE Orders.CustomerID IS NULL;
RIGHT JOIN  # all of the right table 
SELECT Orders.OrderID, Employees.LastName, Employees.FirstName
FROM Orders
RIGHT JOIN Employees ON Orders.EmployeeID = Employees.EmployeeID
ORDER BY Orders.OrderID;          -- every employee, even with no orders
A RIGHT JOIN is just a LEFT JOIN with the tables swapped; most people only use LEFT
CROSS JOIN  # every combination 
SELECT Customers.CustomerName, Orders.OrderID
FROM Customers
CROSS JOIN Orders;
rows = rows(A) & rows(B) & can explode. Adding a WHERE makes it behave like an inner join
Self Join  # a table joined with itself
Give the same table two different aliases
SELECT A.CustomerName AS CustomerName1, B.CustomerName AS CustomerName2, A.City
FROM Customers A, Customers B
WHERE A.CustomerID <> B.CustomerID
AND A.City = B.City
ORDER BY A.City;                  -- customers from the same city
UNION  UNION ALL  # stack the results of several SELECTs
Each SELECT needs the same number of columns, similar types, same order
Column names come from the first SELECT
UNION removes duplicate rows; UNION ALL keeps them (and is faster)
SELECT City FROM Customers
UNION
SELECT City FROM Suppliers
ORDER BY City;                    -- distinct cities from both

SELECT City FROM Customers
UNION ALL
SELECT City FROM Suppliers
ORDER BY City;                    -- duplicates kept

SELECT City, Country FROM Customers WHERE Country='Germany'
UNION
SELECT City, Country FROM Suppliers WHERE Country='Germany'
ORDER BY City;

-- tag where each row came from
SELECT 'Customer' AS Type, ContactName, City, Country FROM Customers
UNION
SELECT 'Supplier', ContactName, City, Country FROM Suppliers;

🧩 Subqueries & Quantifiers

subquery in WHERE  # a SELECT inside a SELECT 
SELECT * FROM Products
WHERE Price > (SELECT AVG(Price) FROM Products);

SELECT * FROM Customers
WHERE CustomerID IN (SELECT CustomerID FROM Orders);
EXISTS  NOT EXISTS  # is the subquery non-empty?
TRUE if the subquery returns at least one row
SELECT SupplierName FROM Suppliers
WHERE EXISTS (
    SELECT ProductName FROM Products
    WHERE Products.SupplierID = Suppliers.SupplierID AND Price < 20
);                                -- suppliers with a product under 20
The subquery refers to the outer table (a *correlated* subquery)
ANY  ALL  SOME  # compare to a set of subquery values
ANY (= SOME) & TRUE if the comparison is true for at least one value
ALL & TRUE only if it is true for every value
SELECT column_name(s) FROM table_name
WHERE column_name operator ANY (SELECT column_name FROM table_name WHERE condition);

SELECT ProductName FROM Products
WHERE ProductID = ANY (SELECT ProductID FROM OrderDetails WHERE Quantity = 10);

SELECT ProductName FROM Products
WHERE ProductID = ALL (SELECT ProductID FROM OrderDetails WHERE Quantity = 10);

SELECT ProductName FROM Products
WHERE Price > ALL (SELECT Price FROM Products WHERE CategoryID = 2);
operator is one of = <> != > >= < <=
INSERT INTO ... SELECT  # copy rows between tables
Source and target column types must match; existing rows in the target are untouched
INSERT INTO Customers (CustomerName, City, Country)
SELECT SupplierName, City, Country FROM Suppliers;

INSERT INTO Customers (CustomerName, City, Country)
SELECT SupplierName, City, Country FROM Suppliers
WHERE Country = 'Germany';
Omitting the column list needs the same number and order of columns in both tables
CREATE TABLE ... AS SELECT  # make a new table from a query 
CREATE TABLE TestTable AS
SELECT CustomerName, ContactName
FROM Customers;
New table gets the selected columns' names/types and the rows; constraints and indexes are not copied

✏️ Changing Data (INSERT / UPDATE / DELETE)

INSERT INTO  # add rows 
-- 1. name the columns (preferred)
INSERT INTO Customers (CustomerName, City, Country)
VALUES ('Cardinal', 'Stavanger', 'Norway');

-- 2. all columns, in table order
INSERT INTO Customers
VALUES (DEFAULT, 'Cardinal', 'Tom B. Erichsen', 'Skagen 21', 'Stavanger', '4006', 'Norway');

-- several rows at once
INSERT INTO Customers (CustomerName, ContactName, Address, City, PostalCode, Country)
VALUES
('Cardinal', 'Tom B. Erichsen', 'Skagen 21', 'Stavanger', '4006', 'Norway'),
('Greasy Burger', 'Per Olsen', 'Gateveien 15', 'Sandnes', '4306', 'Norway'),
('Tasty Tee', 'Finn Egan', 'Streetroad 19B', 'Liverpool', 'L1 0AA', 'UK');
Columns you skip get their DEFAULT / AUTO_INCREMENT value, or NULL
LAST_INSERT_ID() returns the auto-increment id just created
UPDATE  SET  # change rows 
UPDATE Customers
SET ContactName = 'Alfred Schmidt', City = 'Frankfurt'
WHERE CustomerID = 1;

UPDATE Customers SET PostalCode = '00000' WHERE Country = 'Mexico';   -- many rows
No WHERE = EVERY row is updated
DELETE  # remove rows 
DELETE FROM Customers WHERE CustomerName = 'Alfreds Futterkiste';
DELETE FROM Customers;            -- ALL rows (table, columns, indexes stay)
No WHERE = EVERY row is deleted. Tip: run it as a SELECT ... WHERE first to see what would go
TRUNCATE TABLE  # empty a table fast 
TRUNCATE TABLE table_name;
Deletes all rows but keeps the structure, columns and constraints; resets AUTO_INCREMENT
Faster than DELETE FROM t but cannot be rolled back and takes no WHERE

🏗️ Databases & Tables (DDL)

CREATE DATABASE  SHOW DATABASES  # make / list databases 
CREATE DATABASE testDB;
SHOW DATABASES;                   -- list them
USE testDB;                       -- make it current
Needs admin privileges; the name must be unique on the server
DROP DATABASE  # delete a database 
DROP DATABASE testDB;
Permanent: deletes the database and ALL its tables, views, procedures and data
CREATE TABLE  # define columns and types 
CREATE TABLE table_name (
    column1 datatype,
    column2 datatype,
    column3 datatype
);

CREATE TABLE Persons (
    PersonID int,
    LastName varchar(255),
    FirstName varchar(255),
    Address varchar(255),
    City varchar(255)
);
Constraints can go right after each column type (see Constraints section)
DESCRIBE Persons; / SHOW COLUMNS FROM Persons; / SHOW TABLES; show what exists
ALTER TABLE  # change an existing table 
ALTER TABLE Customers ADD Email varchar(255);               -- add column
ALTER TABLE Customers DROP COLUMN Email;                    -- remove column
ALTER TABLE Customers RENAME COLUMN old_name TO new_name;   -- rename column
ALTER TABLE Persons MODIFY COLUMN DateOfBirth year;         -- change data type
ALTER TABLE Customers RENAME TO Clients;                    -- rename table
ALTER TABLE Persons ADD CONSTRAINT ... ;                    -- see Constraints
MODIFY restates the whole column definition (include NOT NULL, DEFAULT, etc. or they are lost)
Changing to a smaller type can truncate or fail on existing data
DROP TABLE  IF EXISTS  # delete a table 
DROP TABLE Shippers;
DROP TABLE IF EXISTS Shippers;    -- no error if it is already gone
Deletes the table and all its data. Cannot drop a table another table references with a FOREIGN KEY & drop the constraint or the child table first
AUTO_INCREMENT  # automatic numeric IDs 
CREATE TABLE Persons (
    Personid int NOT NULL AUTO_INCREMENT,
    LastName varchar(255) NOT NULL,
    FirstName varchar(255),
    Age int,
    PRIMARY KEY (Personid)
);

ALTER TABLE Persons AUTO_INCREMENT = 100;     -- next id will be 100

INSERT INTO Persons (FirstName, LastName) VALUES ('Lars', 'Monsen');   -- id omitted
Starts at 1 and adds 1 for each new row; the column must be a key (usually the PRIMARY KEY)
CREATE INDEX  # speed up searches 
CREATE INDEX idx_lastname ON Persons (LastName);
CREATE INDEX idx_pname ON Persons (LastName, FirstName);   -- multi-column
CREATE UNIQUE INDEX uidx_pid ON Persons (PersonID);        -- no duplicate values

ALTER TABLE Persons DROP INDEX idx_pname;                  -- MySQL's way to remove one
Indexes make SELECT ... WHERE faster but slow down INSERT/UPDATE/DELETE (the index must be maintained)
Only index columns you search/join/sort on often
CREATE VIEW  # a saved query that acts like a table 
CREATE VIEW [Brazil Customers] AS
SELECT CustomerName, ContactName
FROM Customers
WHERE Country = 'Brazil';

SELECT * FROM [Brazil Customers];             -- use it like a table

CREATE OR REPLACE VIEW [Brazil Customers] AS  -- change it later
SELECT CustomerName, ContactName, City
FROM Customers
WHERE Country = 'Brazil';

DROP VIEW [Brazil Customers];
MySQL's own quoting for names with spaces is backticks ( Brazil Customers ); square brackets are SQL Server style. Safest: a name without spaces, e.g. Brazil_Customers
A view stores no data & it runs the query each time

🔒 Constraints

constraints overview  # rules that keep data valid
If an action violates a constraint, the action is aborted
Set when the table is created (CREATE TABLE) or later (ALTER TABLE)
ConstraintEnsures
NOT NULLcolumn cannot be NULL
UNIQUEall values in the column are different
PRIMARY KEYunique row identifier (= NOT NULL + UNIQUE)
FOREIGN KEYlink to another table; blocks changes that would break the link
CHECKvalues satisfy a condition
DEFAULTvalue used when none is supplied
CREATE INDEXfaster data retrieval
NOT NULL  # value required 
CREATE TABLE Persons (
    ID int NOT NULL,
    LastName varchar(255) NOT NULL,
    FirstName varchar(255) NOT NULL,
    Age int
);

ALTER TABLE Persons MODIFY Age int NOT NULL;     -- add
ALTER TABLE Persons MODIFY Age int NULL;         -- remove
UNIQUE  # no duplicates (many allowed per table) 
CREATE TABLE Persons (
    ID int NOT NULL,
    LastName varchar(255) NOT NULL,
    UNIQUE (ID)
);

-- named, multi-column
CREATE TABLE Persons (
    ID int NOT NULL,
    LastName varchar(255) NOT NULL,
    CONSTRAINT UC_Person UNIQUE (ID, LastName)
);

ALTER TABLE Persons ADD UNIQUE (ID);
ALTER TABLE Persons ADD CONSTRAINT UC_Person UNIQUE (ID, LastName);
ALTER TABLE Persons DROP INDEX UC_Person;        -- MySQL drops it as an index
Many UNIQUE constraints per table, but only ONE PRIMARY KEY
PRIMARY KEY  # identifies each row
Unique + not NULL; one per table; may span several columns
CREATE TABLE Persons (
    ID int PRIMARY KEY,
    LastName varchar(255) NOT NULL,
    FirstName varchar(255),
    Age int
);

-- multi-column, named
CREATE TABLE Persons (
    ID int,
    LastName varchar(255),
    FirstName varchar(255),
    CONSTRAINT PK_Person PRIMARY KEY (ID, LastName)
);

ALTER TABLE Persons ADD PRIMARY KEY (ID);
ALTER TABLE Persons ADD CONSTRAINT PK_Person PRIMARY KEY (ID, LastName);
ALTER TABLE Persons DROP PRIMARY KEY;
With ALTER TABLE ... ADD PRIMARY KEY the column(s) must already be NOT NULL
FOREIGN KEY  # link a child table to a parent
A column in the **child** table that refers to the PRIMARY KEY of the **parent** table
Blocks inserting a child value that does not exist in the parent, and deleting a parent row that still has children
CREATE TABLE Orders (
    OrderID int PRIMARY KEY,
    OrderNumber int NOT NULL,
    PersonID int,
    CONSTRAINT fk_Person
        FOREIGN KEY (PersonID)
        REFERENCES Persons(PersonID)
);

ALTER TABLE Orders
ADD CONSTRAINT fk_Person
FOREIGN KEY (PersonID) REFERENCES Persons(PersonID);

ALTER TABLE Orders DROP FOREIGN KEY fk_Person;
Optional: ON DELETE CASCADE / ON UPDATE CASCADE / ON DELETE SET NULL after REFERENCES
CHECK  # a condition every row must meet 
CREATE TABLE Persons (
    ID int NOT NULL,
    Age int,
    City varchar(255),
    CHECK (Age >= 18)
);

-- named, multi-column
CREATE TABLE Persons (
    ID int NOT NULL,
    Age int,
    City varchar(255),
    CONSTRAINT CHK_Person CHECK (Age >= 18 AND City = 'Sandnes')
);

ALTER TABLE Persons ADD CHECK (Age >= 18);
ALTER TABLE Persons ADD CONSTRAINT CHK_PersonAge CHECK (Age >= 18 AND City = 'Sandnes');
ALTER TABLE Persons DROP CHECK CHK_PersonAge;
Enforced from MySQL 8.0.16 on (older versions parsed and silently ignored CHECK)
DEFAULT  # fallback value 
CREATE TABLE Persons (
    ID int PRIMARY KEY,
    LastName varchar(255) NOT NULL,
    City varchar(255) DEFAULT 'Sandnes'
);

CREATE TABLE Orders (
    ID int PRIMARY KEY,
    OrderNumber int NOT NULL,
    OrderDate date DEFAULT CURRENT_DATE()          -- system value
);

ALTER TABLE Persons ALTER City SET DEFAULT 'Sandnes';
ALTER TABLE Persons ALTER City DROP DEFAULT;

⚙️ Stored Procedures

CREATE PROCEDURE  CALL  # saved, reusable SQL with parameters
Benefits: reuse from many apps, precompiled, permissions can be granted per procedure, update in one place
DELIMITER // temporarily changes the statement terminator so the ; inside the body does not end CREATE
DELIMITER //
CREATE PROCEDURE GetCustomersByCity(IN city_name VARCHAR(50))
BEGIN
    SELECT * FROM Customers
    WHERE City = city_name;
END //
DELIMITER ;

CALL GetCustomersByCity('London');

-- several parameters
DELIMITER //
CREATE PROCEDURE GetCustomersByCityAndZip(IN city_name VARCHAR(50), IN zip VARCHAR(10))
BEGIN
    SELECT * FROM Customers
    WHERE City = city_name AND PostalCode = zip;
END //
DELIMITER ;

CALL GetCustomersByCityAndZip('London', 'WA1 1DP');

DROP PROCEDURE GetCustomersByCity;
DROP PROCEDURE IF EXISTS GetCustomersByCity;
The W3Schools page writes parameters as @City VARCHAR(50) with no parentheses (SQL Server style) & real MySQL wants (IN name TYPE, ...) as above; @name in MySQL is a user variable
Parameter modes: IN (default, input), OUT (returned), INOUT (both)

🛡️ Security — Injection & Prepared Statements

SQL injection  # user input turned into SQL
Attacker types SQL into a form field and your code pastes it into a query string
-- code builds:  "SELECT * FROM Users WHERE UserId = " + txtUserId
-- user types:   105 OR 1=1
SELECT * FROM Users WHERE UserId = 105 OR 1=1;          -- 1=1 is always true: every user returned

-- login form:   uName = " or ""="   pass = " or ""="
SELECT * FROM Users WHERE Name ="" or ""="" AND Pass ="" or ""=""    -- always true

-- batched statements
-- user types:   105; DROP TABLE Suppliers
SELECT * FROM Users WHERE UserId = 105; DROP TABLE Suppliers;
Never build SQL by concatenating user input
Defences: **parameterized queries / prepared statements**, validate input, least-privilege DB account, no multi-statement execution
prepared statements  # placeholders keep data separate from code
SQL is compiled once with ? placeholders; the values are sent separately and can never be run as SQL
// PHP (mysqli)
$stmt = $conn->prepare("INSERT INTO MyGuests (firstname, lastname, email) VALUES (?, ?, ?)");
$stmt->bind_param("sss", $firstname, $lastname, $email);
$firstname = "John"; $lastname = "Doe"; $email = "john@example.com";
$stmt->execute();
bind_param type letters: i integer, d double, s string, b blob
# Python (mysql-connector) - %s placeholders, never f-strings
cur.execute("SELECT * FROM Customers WHERE City = %s AND Country = %s", (city, country))
-- plain MySQL
PREPARE stmt FROM 'SELECT * FROM Customers WHERE City = ?';
SET @c = 'London';
EXECUTE stmt USING @c;
DEALLOCATE PREPARE stmt;
Placeholders can stand in for values only & not for table or column names

⚠️ MySQL Traps & Gotchas

Classic mistakes  # check this list when a query misbehaves
UPDATE or DELETE without WHERE hits EVERY row
DROP DATABASE / DROP TABLE / TRUNCATE are permanent & no undo
= NULL never matches; use IS NULL / IS NOT NULL
Anything + NULL = NULL (use COALESCE/IFNULL)
COUNT(col) skips NULLs, COUNT(*) does not
NOT IN (subquery) returns nothing if the subquery yields a NULL
WHERE cannot use aggregates (WHERE COUNT(*) > 5 & error); use HAVING
Selected columns not in GROUP BY or an aggregate & error under ONLY_FULL_GROUP_BY
AND is evaluated before OR & add parentheses
-- comment needs a space after it: --
DATETIME with a time part never equals a plain date string
BETWEEN includes both ends (and with dates, '...-31' means midnight, losing that day's times)
LIKE '%x' can't use an index; and a stray %/_ in user input acts as a wildcard
Double quotes are strings by default in MySQL (identifiers use backticks) & unless ANSI_QUOTES mode is on
Integer division: / gives decimals in MySQL, DIV gives integers
FLOAT/DOUBLE for money & rounding errors; use DECIMAL
Building SQL with string concatenation & SQL injection; use prepared statements
ALTER TABLE ... MODIFY replaces the whole column definition & restate NOT NULL, DEFAULT, AUTO_INCREMENT
Can't drop a table that a foreign key references; drop the child (or the constraint) first
Table-name case sensitivity differs between Linux/Mac and Windows
SELECT * + joins gives duplicate column names; list columns explicitly
