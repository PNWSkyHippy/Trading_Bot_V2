🚀 Getting Started & Upgrading

What is React  # front-end library for UI components
A JavaScript **library** for building user interfaces out of reusable **components** (made by Facebook/Jordan Walke; public release 2013; current series 19.x)
Keeps a **virtual DOM** in memory, compares old vs new, and changes only what differs in the real DOM
You describe *what the UI should look like for the current data*; React works out the DOM updates (declarative)
Needs: HTML, CSS and JavaScript basics (see ES6 section)
Used to build single-page apps (SPAs); a router library adds multiple 'pages'
Create an app (Vite)  # Node.js + npm + build tool 
node -v                                         # need Node.js installed
npm create vite@latest my-react-app -- --template react
cd my-react-app
npm install
npm run dev                                     # dev server at http://localhost:5173/
npm run build                                   # production build into dist/
Vite is the build tool used here (Create React App is retired)
Typical layout: index.html (has <div id="root">), src/main.jsx (entry), src/App.jsx, package.json
Render to the page  # createRoot 
import { createRoot } from 'react-dom/client';

createRoot(document.getElementById('root')).render(
  <h1>Hello React!</h1>
);

// with an app component and StrictMode (Vite default)
import { StrictMode } from 'react';
import App from './App.jsx';
createRoot(document.getElementById('root')).render(
  <StrictMode><App /></StrictMode>
);
render() replaces whatever is inside the root element; call createRoot once
StrictMode runs extra checks in development (renders and effects run twice on purpose)
Upgrade to React 19  # two steps 
npm i react@latest react-dom@latest

// Before (old API)
import ReactDOM from 'react-dom';
ReactDOM.render(<h1>Hello React!</h1>, document.getElementById('root'));

// After
import { createRoot } from 'react-dom/client';
createRoot(document.getElementById('root')).render(<h1>Hello React!</h1>);
The W3Schools page says old ReactDOM.render still runs 'like React 17' & that was true for React 18; React 19 REMOVED ReactDOM.render, so switch to createRoot

🧬 ES6 Refresher (what React leans on)

let  const  var  # variables 
var a = 1;          // function-scoped, hoisted - avoid
let b = 2;          // block-scoped, reassignable
const c = 3;        // block-scoped, cannot be reassigned

const arr = [1, 2];
arr.push(3);        // OK - the array itself may change; only the binding is fixed
Default to const; use let only when you must reassign. React state is never mutated & you replace it
Arrow functions  # => 
const hello = () => 'Hello World!';             // implicit return
const add = (a, b) => a + b;

const big = (a, b) => {                         // braces = write 'return'

};
Arrows have no own this & they use the surrounding this (why class handlers can be arrows)

const [first, second] = ['red', 'green', 'blue'];     // by position
const [, , third] = ['red', 'green', 'blue'];         // skip with commas

const both = [...arr1, ...arr2];                      // new array
const copy = [...arr];

Modules  import  export  # split code into files

📝 JSX

JSX basics  # HTML-like syntax inside JavaScript 
const el = <h1>Hello</h1>;                       // JSX
const el2 = React.createElement('h1', null, 'Hello');   // what it compiles to
Must return ONE parent element & wrap in a <div> or a fragment <>...</> (no extra DOM node)
Every tag must be closed: <input />, <br />, <img src="a.png" />
Component names start with a Capital letter (<Car />); lower case means a plain HTML tag
return (
  <>
    <h1>Title</h1>
    <p>Text</p>
  </>
);
Comments inside JSX: {/* like this */}
JSX expressions  { }  # JavaScript inside markup 
const name = 'Ada';
<h1>Hello {name}!</h1>
<p>{5 + 5}</p>
<p>{user.first + ' ' + user.last}</p>
<p>{items.length > 0 ? 'Has items' : 'Empty'}</p>
<img src={photo.url} alt={photo.alt} />
Curly braces hold any JS EXPRESSION (value-producing): variables, math, calls, ternaries & not statements like if/for
Objects can't be rendered directly ({user} & error); render a field or JSON.stringify
true, false, null, undefined render nothing; 0 DOES render
JSX attributes  # camelCase and the renames
HTMLJSX
classclassName
for (label)htmlFor
onclickonClick
onchangeonChange
tabindextabIndex

readonlyreadOnly
style="color:red"style={{ color: 'red' }}
checked (boolean)checked={true}
<div className="box" id={`item-${id}`} style={{ backgroundColor: 'navy', fontSize: 20 }}>
<label htmlFor="n">Name</label> <input id="n" disabled />
const style = { color: 'red', padding: 10 };      // numbers = px
<p style={style}>Styled</p>
style takes an OBJECT with camelCase keys: backgroundColor, not background-color (hence the double braces: outer = expression, inner = object)
data-* and aria-* attributes keep their dashes
Conditional rendering in JSX  # if / && / ternary 
// 1. if with early return
function Goal({ isGoal }) {
  if (isGoal) return <MadeGoal />;
  return <MissedGoal />;
}

// 2. && : render something or nothing
{cars.length > 0 && <h2>You have {cars.length} cars</h2>}

// 3. ternary : this or that
{isLoggedIn ? <Logout /> : <Login />}

// 4. variable holding JSX
let content = <Login />;
if (user) content = <Welcome />;
return <div>{content}</div>;
{count && <X />} renders a literal 0 when count is 0 & use {count > 0 && <X />}
A component can return null; to render nothing

🧱 Components, Props & Children

Function components  # the modern default
A function whose name starts with a capital letter and that returns JSX
function Car() {
  return <h2>Hi, I am a Car!</h2>;
}
const Car2 = () => <h2>Arrow works too</h2>;

// use it like a tag
<Car />

// nest components
function Garage() {
  return (
    <>
      <h1>Who lives in my Garage?</h1>
      <Car />
    </>
  );
}
One component per file; export default Car; then import Car from './Car';
Props  # inputs, read-only 
function Car(props) {
  return <h2>I am a {props.color} Car!</h2>;
}
<Car color="red" />                       // string
<Car year={2024} electric={true} />       // non-strings need { }
<Car brand={{ name: 'Ford', model: 'Mustang' }} />    // object: props.brand.name
<Car onHonk={() => alert('beep')} />      // function as a prop (child -> parent messages)

// pass a value from a variable
const c = 'blue';  <Car color={c} />
Props flow DOWN (parent & child). To send data UP, the parent passes a callback function as a prop
Props are read-only & never write props.x = ...; to change something use state
Destructuring props  defaults  # cleaner parameters 
function Car({ color, year = 2020 }) {      // default if not passed
  return <p>{color} {year}</p>;
}
function Card({ title, ...rest }) {         // rest = all other props
  return <div {...rest}><h3>{title}</h3></div>;
}
props.children  # content between the tags 
function Card({ children }) {
  return <div className="card">{children}</div>;
}
<Card>
  <h2>Anything in here</h2>
  <p>becomes children</p>
</Card>
Great for wrappers: layouts, modals, panels, themes
Class components  # legacy style (still works) 
import { Component } from 'react';

class Car extends Component {
  constructor(props) {
    super(props);                       // always first
    this.state = { color: 'red' };
  }
  componentDidMount() { /* after first render: fetch data, subscribe */ }
  componentDidUpdate(prevProps, prevState) { /* after a re-render */ }
  componentWillUnmount() { /* cleanup */ }
  changeColor = () => this.setState({ color: 'blue' });    // arrow keeps `this`
  render() {
    return (
      <div>
        <h2>My {this.state.color} {this.props.brand}</h2>
        <button onClick={this.changeColor}>Change</button>
      </div>
    );
  }
}
State only changes via this.setState({...}) (merges into the old state); props via this.props
Lifecycle: **mount** (constructor, render, componentDidMount) & **update** (render, componentDidUpdate) & **unmount** (componentWillUnmount)
New code should use function components + Hooks; hooks do NOT work inside classes
Higher-Order Components  # function that takes a component, returns one 
function withLoading(Wrapped) {
  return function WithLoading({ loading, ...props }) {
    if (loading) return <p>Loading...</p>;
    return <Wrapped {...props} />;
  };
}
const UserListWithLoading = withLoading(UserList);
<UserListWithLoading loading={isLoading} users={users} />
Pattern for sharing behaviour; today custom Hooks usually do this job more simply

🖱️ Lists, Keys & Events

Lists  map()  key  # render arrays 
function Garage() {
  const cars = [
    { id: 1, brand: 'Ford' },
    { id: 2, brand: 'BMW' },
    { id: 3, brand: 'Audi' },
  ];
  return (
    <ul>
      {cars.map(car => <li key={car.id}>{car.brand}</li>)}
    </ul>
  );
}
key goes on the OUTERMOST element returned by map; must be unique among siblings and stable (a database id)
Avoid the array index as key if the list can reorder, insert or delete & state gets attached to the wrong item
key is not passed down as a prop & pass a separate id prop if the child needs it
Events  # camelCase handlers, functions not strings 
function Ball() {
  const shoot = () => alert('Great Shot!');
  const shootWith = (msg) => alert(msg);
  return (
    <>
      <button onClick={shoot}>Take the shot!</button>
      <button onClick={() => shootWith('Goal!')}>With argument</button>
      <input onChange={(e) => console.log(e.target.value)} />
      <form onSubmit={(e) => { e.preventDefault(); /* ... */ }}>
    </>
  );
}
Common: onClick, onChange, onSubmit, onKeyDown, onFocus, onBlur, onMouseEnter, onMouseLeave
Handler receives an event object e (e.target, e.target.value, e.preventDefault())
onClick={shoot()} CALLS it during render; pass the function: onClick={shoot} or wrap () => shoot(x)

📋 Forms

Controlled input  # state is the single source of truth 
import { useState } from 'react';

function MyForm() {
  const [name, setName] = useState('');
  const handleSubmit = (e) => {
    e.preventDefault();                    // stop the page reload
    alert(`The name you entered was: ${name}`);
  };
  return (
    <form onSubmit={handleSubmit}>
      <label>Enter your name:
        <input type="text" value={name} onChange={(e) => setName(e.target.value)} />
      </label>
      <input type="submit" />
    </form>
  );
}
Pattern: value={state} + onChange that updates state. React, not the DOM, owns the value
value without onChange makes the field read-only
Multiple fields, one handler  # key by name attribute 
const [inputs, setInputs] = useState({});
const handleChange = (e) => {
  const { name, value } = e.target;
  setInputs(values => ({ ...values, [name]: value }));     // [name] = computed key
};
<input type="text" name="username" value={inputs.username || ''} onChange={handleChange} />
<input type="number" name="age" value={inputs.age || ''} onChange={handleChange} />
Initialize with {}, and use || '' so inputs start controlled
textarea  select  # use value, not children 
const [text, setText] = useState('Some starting text');
<textarea value={text} onChange={(e) => setText(e.target.value)} />

const [car, setCar] = useState('Volvo');
<select value={car} onChange={(e) => setCar(e.target.value)}>
  <option value="Ford">Ford</option>
  <option value="Volvo">Volvo</option>
</select>
Unlike HTML, <textarea> takes value (self-closing), and <select> takes value on the select instead of selected on an option
checkbox  radio  # checked vs value 
const [on, setOn] = useState(false);
<input type="checkbox" checked={on} onChange={(e) => setOn(e.target.checked)} />

const [pick, setPick] = useState('');
<input type="radio" name="car" value="Ford"  checked={pick === 'Ford'}  onChange={(e) => setPick(e.target.value)} /> Ford
<input type="radio" name="car" value="Volvo" checked={pick === 'Volvo'} onChange={(e) => setPick(e.target.value)} /> Volvo
Checkbox reads e.target.checked (boolean); radio group reads e.target.value and compares to its own value
Several checkboxes & one state object like { ford: false, volvo: true }, updated by name
Submit  # onSubmit on the form
Put the handler on <form onSubmit>, not on the button & Enter key then works too
Always call e.preventDefault() unless you want the browser to reload
const handleSubmit = (e) => {
  e.preventDefault();
  console.log(inputs);        // send to your API here
};

🪝 Hooks

Hooks overview  rules  # functions that start with use
Hooks let function components use state, side effects, context, refs& (React 16.8+)
HookFor
useStatea value that re-renders the component when it changes
useEffectside effects: fetching, timers, subscriptions, manual DOM
useRefa mutable box that survives renders / a DOM element handle
useContextread shared data without passing props down
useReducercomplex state via (state, action) & newState
useCallbackkeep the same function between renders
useMemokeep the same computed value between renders
useTransitionmark an update non-urgent
Rules: call Hooks only at the TOP LEVEL of a component or custom Hook & never inside if, loops or nested functions; only from React function components or other Hooks
useState  # remember a value 
import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);                 // [value, setter] = useState(initial)
  return (
    <>
      <p>Clicked {count} times</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
      <button onClick={() => setCount(c => c + 1)}>+1 (safe)</button>   // updater form
    </>
  );
}

const [user, setUser] = useState({ name: 'Ada', age: 30 });
setUser(prev => ({ ...prev, age: 31 }));                 // objects: spread + change
const [items, setItems] = useState([]);
setItems(prev => [...prev, newItem]);                    // add
setItems(prev => prev.filter(i => i.id !== id));         // remove
setItems(prev => prev.map(i => i.id === id ? { ...i, done: true } : i));   // edit
The setter schedules a re-render; the new value shows up on the NEXT render (the variable you hold doesn't change mid-function)
When the new value depends on the old, use the updater form setX(prev => ...)
Expensive initial value? Pass a function: useState(() => compute()) (runs once)
Never mutate state (items.push(x), user.age = 31) & React sees the same reference and may not re-render
useEffect  # side effects after render 
import { useEffect } from 'react';

useEffect(() => { /* runs after EVERY render */ });
useEffect(() => { /* runs once, after first render */ }, []);
useEffect(() => { /* runs when count changes */ }, [count]);

useEffect(() => {
  const id = setInterval(() => setCount(c => c + 1), 1000);
  return () => clearInterval(id);          // cleanup: before re-run and on unmount
}, []);

// fetching
useEffect(() => {
  let ignore = false;
  fetch(`https://jsonplaceholder.typicode.com/todos?userId=${id}`)
    .then(r => r.json())
    .then(data => { if (!ignore) setTodos(data); });
  return () => { ignore = true; };
}, [id]);
Dependency array: none = every render; [] = mount only; [a, b] = when a or b change
List EVERY reactive value (props, state, derived functions) the effect uses in the array
setState in an effect with no/incorrect deps & infinite render loop
In StrictMode dev, effects run mount & cleanup & mount once to expose missing cleanup (not a bug)
useRef  # persistent box, DOM handle 
import { useRef } from 'react';

const inputRef = useRef(null);
<input ref={inputRef} />
<button onClick={() => inputRef.current.focus()}>Focus</button>

const renders = useRef(0);          // value that survives renders WITHOUT triggering one
renders.current = renders.current + 1;

const prev = useRef();              // previous value pattern
useEffect(() => { prev.current = value; }, [value]);
Change .current freely & it does NOT cause a re-render (unlike state)
Don't read/write ref.current during rendering; do it in handlers and effects
useContext  # shared data without prop drilling 
import { createContext, useContext, useState } from 'react';

const UserContext = createContext(null);                // 1. create

function App() {
  const [user, setUser] = useState('Ada');
  return (
    <UserContext.Provider value={user}>                 // 2. provide
      <Layout />
    </UserContext.Provider>
  );
}

function Profile() {
  const user = useContext(UserContext);                 // 3. consume anywhere below
  return <p>Hello {user}</p>;
}
Every consumer re-renders when the Provider's value changes; pass { user, setUser } to share the setter too
Good for: theme, current user, language. Not a replacement for all state
React 19 also allows <UserContext value={user}> without .Provider
useReducer  # state + an update function you write 
import { useReducer } from 'react';

function reducer(state, action) {
  switch (action.type) {
    case 'add':    return [...state, action.todo];
    case 'toggle': return state.map(t => t.id === action.id ? { ...t, done: !t.done } : t);
    case 'remove': return state.filter(t => t.id !== action.id);
    default:       return state;
  }
}

const [todos, dispatch] = useReducer(reducer, []);      // (reducer, initialState)
dispatch({ type: 'toggle', id: 3 });
Use when state is an object/array with many update kinds; the reducer must be pure and never mutate
useCallback  # cache a function 
import { useCallback } from 'react';
import { memo } from 'react';

const Todos = memo(function Todos({ todos, addTodo }) { ... });   // skips re-render if props same

const addTodo = useCallback(() => {
  setTodos(t => [...t, 'New Todo']);
}, []);                                  // same function every render
<Todos todos={todos} addTodo={addTodo} />
A new function is created on every render, so child props change; useCallback + React.memo stops needless child re-renders
useMemo  # cache a computed value 
import { useMemo } from 'react';

const total = useMemo(() => expensiveCalc(count), [count]);   // recompute only when count changes
useMemo caches a VALUE, useCallback caches a FUNCTION (useCallback(fn, deps) & useMemo(() => fn, deps))
Optimization only & reach for it when you actually measure slowness
Custom Hooks  # reuse stateful logic
A function whose name starts with use that calls other Hooks. Put it in its own file e.g. useFetch.js
// useFetch.js
import { useState, useEffect } from 'react';
const useFetch = (url) => {
  const [data, setData] = useState(null);
  useEffect(() => {
    fetch(url).then(res => res.json()).then(setData);
  }, [url]);
  return [data];
};
export default useFetch;

// Home.jsx
import useFetch from './useFetch';
const Home = () => {
  const [data] = useFetch('https://jsonplaceholder.typicode.com/todos');
  return <>{data && data.map(item => <p key={item.id}>{item.title}</p>)}</>;
};
Each component calling the Hook gets its OWN copy of the state (logic is shared, data is not)
useTransition  # keep the UI responsive 
import { useState, useTransition } from 'react';

const [input, setInput] = useState('');
const [query, setQuery] = useState('');
const [isPending, startTransition] = useTransition();

const handleChange = (e) => {
  setInput(e.target.value);                         // urgent: input updates immediately
  startTransition(() => setQuery(e.target.value));  // non-urgent: heavy list can lag
};
{isPending && <p>Loading results...</p>}
Returns [isPending, startTransition]; use for filtering big lists, not for typing itself
forwardRef  ref as a prop  # let a parent reach a child's DOM node 
// React 18 and earlier
import { forwardRef, useRef } from 'react';
const MyInput = forwardRef((props, ref) => <input ref={ref} {...props} />);

function App() {
  const inputRef = useRef();
  return (
    <>
      <MyInput ref={inputRef} placeholder="Type here..." />
      <button onClick={() => inputRef.current.focus()}>Focus Input</button>
    </>
  );
}

// React 19: ref is just a normal prop on function components
function MyInput2({ ref, ...props }) { return <input ref={ref} {...props} />; }
Only when you need direct DOM access (focus, measure, animate, 3rd-party widgets); prefer props/state otherwise
In React 19 forwardRef is no longer needed and is slated for deprecation
Suspense  lazy  # loading fallbacks and code splitting 
import { Suspense, lazy } from 'react';

const Cars = lazy(() => import('./Cars'));      // loaded only when first rendered

function App() {
  return (
    <Suspense fallback={<div>Loading...</div>}>
      <Cars />
      <Sidebar />          {/* one Suspense can wrap several lazy components */}
    </Suspense>
  );
}
lazy() loads a component dynamically; Suspense shows the fallback (any JSX) until it is ready
Also used with Suspense-enabled data fetching (frameworks, use() in React 19)
Portals  # render outside the parent DOM node 
import { createPortal } from 'react-dom';

function Modal({ children }) {
  return createPortal(
    <div className="modal">{children}</div>,
    document.body                                  // where it really lands
  );
}
createPortal(children, domNode); great for modals, tooltips, dialogs that must escape overflow:hidden or z-index traps
Events still bubble through the React tree as if the portal were a normal child

🧭 React Router

Basic routing  # Link, Routes, Route 
npm install react-router-dom

import { BrowserRouter, Routes, Route, Link } from 'react-router-dom';

function App() {
  return (
    <BrowserRouter>
      <nav>
        <Link to="/">Home</Link> | <Link to="/about">About</Link>
      </nav>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
        <Route path="*" element={<NotFound />} />      {/* catch-all */}
      </Routes>
    </BrowserRouter>
  );
}
BrowserRouter wraps the app; Link changes the URL WITHOUT a page reload (don't use <a href> for in-app links)
Version 7 also exports everything from the react-router package; react-router-dom still works

import { Outlet } from 'react-router-dom';

function Products() {
  return (
    <div>
      <h1>Products</h1>
      <Link to="/products/car">Cars</Link> | <Link to="/products/bike">Bikes</Link>
      <Outlet />                       {/* child route renders here */}
    </div>
  );
}

⚠️ React Traps & Gotchas

Classic mistakes  # check this list when something misbehaves
Mutating state (push, obj.x = 1) & always make a new array/object
onClick={fn()} calls immediately on render; use onClick={fn} or () => fn()
State updates are asynchronous: setCount(count+1); console.log(count) shows the OLD value
Several setCount(count + 1) in one handler only add 1; use setCount(c => c + 1)
Missing key (or index as key on reorderable lists) & warnings and wrong UI state
useEffect with no dependency array runs every render; setting state inside it loops forever
Stale closures: an effect/callback with missing deps keeps old values
Forgetting effect cleanup (timers, listeners, subscriptions) & leaks and double events
Hooks inside if/loops/nested functions & 'rendered fewer hooks' errors
Lower-case component names (<car />) are treated as HTML tags
Returning two siblings without a wrapper & use <>...</>
class / for / onclick in JSX & className / htmlFor / onClick
Style as a string (style="color:red") & must be an object style={{color:'red'}}
{count && <X/>} renders 0 when count is 0
Rendering an object as a child & 'Objects are not valid as a React child'
Controlled input switching from undefined to a value & give it an initial ''
Forgot e.preventDefault() in a form submit & page reloads and state is lost
StrictMode double-invoking renders/effects in dev is intentional, not a bug
Props are read-only; to change them the parent must change its state
ReactDOM.render is gone in React 19; use createRoot
Using <a href> instead of <Link> reloads the whole app
