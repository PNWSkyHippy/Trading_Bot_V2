⚠️ Common Errors

TypeError  # wrong type used in an operation
Caused by: "score: " + 95 — can't concatenate str + int
Fix: "score: " + str(95) or use an f-string
NameError  # using a variable before it's defined
Caused by: print(score) before score = 0 is set
Fix: define the variable before using it
ZeroDivisionError  # dividing by zero
Caused by: 10 / 0 or 10 // 0
Fix: check if divisor != 0: before dividing
ValueError  # conversion fails because the value is wrong type or format
Caused by: int("hello") — can't convert non-numeric string
Also: int("3.14") — must go through float first: int(float("3.14"))
IndentationError  # code block not indented correctly
Python uses 4 spaces per indent level (tabs or spaces — never mixed)
All code inside a function, if block, or loop must be indented one level
UnboundLocalError  # variable used before assigned inside a function
Caused by reading a global variable then trying to assign to it locally
Fix: pass values as parameters instead of relying on globals
IndexError: list index out of range  # index position doesn't exist
Caused by: items[5] on a 5-item list (valid range: 0–4)
Valid indexes: 0 to len(list) - 1
Fix: guard with if index < len(list): before accessing
f-string quote collision  # same quote style inside and outside an f-string breaks it
Caused by: f"...{cart["sku"]}..." — inner double quote closes the string early
Fix: use a different quote style inside than outside — f"...{cart['sku']}..."
Also watch for a missing closing quote at end of line — Python then thinks the string never ends
assigning to a method call  # SyntaxError — a method call can't be the left side of =
Caused by: counts.get(fruit, 0) = val + 1 — .get() returns a value, it isn't a storage location
Fix: assign through bracket indexing instead — counts[fruit] = counts.get(fruit, 0) + 1
.get() is safe to READ on the right side of =; never valid on the left side
looping .items() on an empty dict  # silently does nothing — no error, just skipped
Caused by: for key, val in counts.items(): when counts is still {} on that pass
Fix: loop over the SOURCE list, and read/write the accumulator dict by key inside that loop — don't loop over the accumulator itself
# WRONG — counts starts empty, inner loop never runs
counts = {}
for fruit in ['apple', 'pear']:
    for key, val in counts.items():
        ...

# RIGHT — loop the source, index into counts directly
counts = {}
for fruit in ['apple', 'pear']:
    counts[fruit] = counts.get(fruit, 0) + 1
reset-vs-increment counting bug  # assigning = 1 in BOTH if/else branches resets the tally every time
Broken: if code in counts: counts[code] = 1 else: counts[code] = 1 — every sighting resets to 1
Fixed: only the first-seen branch assigns = 1; the already-seen branch must use += 1
Manual, verbose equivalent of the one-liner counts[code] = counts.get(code, 0) + 1
counts = {}
for code in errors:
    if code in counts:
        counts[code] += 1   # must increment, not reset
    else:
        counts[code] = 1
{a, b} set instead of a linked record  # curly braces with commas but no colons is always a SET
Intending to pair two values, e.g. {title, year}, actually creates a set of two loose items
A set loses key-based lookup entirely — no way to find the title from the year or vice versa
Fix for "group by two things": a nested dict-of-dict-of-list built with chained .setdefault()
{} with commas but no colons is ALWAYS a set, never a paired record — {} alone (no commas) is a dict

🔧 Functions

def function_name(param):  # define a reusable named block of code
Body must be indented (4 spaces)
Parameters = variable names in the () at definition
Arguments = actual values passed when calling the function
Multiple parameters: def add(a, b):
No params: def greet():
Functions implicitly return None if no return statement
def greet(name):
    print(f"Hello, {name}!")

greet("Ron")  # argument is "Ron"
return value  # exits the function and sends a value back to the caller
return bare or return None — exits without a value
Code after a return never runs
Multiple return paths are fine — only one runs per call
Capture returned value: result = my_function(x)
def add(a, b):
    return a + b

total = add(3, 4)  # total = 7
return a, b  # return multiple values at once — caller unpacks them into separate variables
Comma-separated values after return are packaged together as a tuple
Caller unpacks positionally: cart, ok = remove_item(cart, item)
Number of variables on the left must match the number of values returned
Common use: return both a result and a status flag from one call
def remove_item(cart, item):
    if item in cart:
        cart.remove(item)
        return cart, True
    return cart, False

cart, removed_ok = remove_item(cart, "apple")
if not removed_ok:
    print("Item not found")
guard clause  # early return at the top of a function to handle edge cases first
Check for invalid/special cases at the top, return early
Avoids deeply nested if/else — keeps the main logic flat and readable
def divide(a, b):
    if b == 0:
        return None   # guard: handle bad input first
    return a / b      # main logic
local scope  # variables inside a function only exist inside that function
Variables defined inside a function disappear when the function ends
Can READ a global variable from inside a function
Cannot ASSIGN to a global variable without global keyword — creates a new local one instead
Assigning then reading causes UnboundLocalError
Best practice: pass values in as parameters instead of relying on globals

🔀 Control Flow — if / elif / else

if condition:   elif condition:   else:  # branching — only ONE branch runs
if — first check; runs if condition is True
elif — checked only if all prior conditions were False
else — runs when no condition matched (no condition needed; optional)
"First true wins" — order matters; put specific conditions before general ones
if score >= 90:
    grade = "A"
elif score >= 80:
    grade = "B"
elif score >= 70:
    grade = "C"
elif score >= 60:
    grade = "D"
else:
    grade = "F"
<   >   <=   >=   ==   !=  # comparison operators — return True or False
< less than    > greater than
<= less than or equal    >= greater than or equal
== equal to (comparison) — NOT = which is assignment
!= not equal to
Chained comparison: 10 <= temp < 25 — both conditions in one expression
and   or   not  # logical operators to combine conditions
and — True only if BOTH sides are True
or — True if EITHER side is True
not — flips True ↔ False
Short-circuiting: and stops at first False; or stops at first True
if age >= 18 and has_id:
    print("allowed")
if not is_banned:
    print("welcome")
is   /   is not  # identity check — preferred way to test for None
x is None — preferred over x == None
x is not None — confirms something has a value
== checks value equality; is checks same object in memory
if result is None:
    print("no result")
"text" in string  # checks if a substring (or value) exists inside a string or list
"cat" in "concatenate" → True
"cat" not in "dog" → True
Case-sensitive: "Cat" in "cat" → False
Works on lists too: 5 in [1, 3, 5] → True
decision table → if/elif/else  # turn rows of a logic table into branches
Each table row becomes one if / elif branch
Check for overlaps: one value shouldn't match two rows
Check for gaps: every possible value should match at least one row
Flat if/elif/else is better than deeply nested ifs

🔁 Loops

for i in range(stop)  # loop from 0 to stop-1
range(5) → 0, 1, 2, 3, 4
range(start, stop) → start to stop-1
range(start, stop, step) → with custom step
range(1, 11) → 1 through 10 (stop 11 not included)
range(0, 10, 2) → 0, 2, 4, 6, 8  (evens)
range(10, 0, -1) → 10, 9, 8, … 1  (countdown)
for i in range(5):
    print(i)           # 0 1 2 3 4

for i in range(1, 6):
    print(i)           # 1 2 3 4 5
for item in list:  # loop directly over list values — no index needed
Use when you only need the value, not the position
Cleaner and shorter than range(len(list)) when index isn't used
for i in range(len(list)): — use this version when you need the index too
# value-based (preferred when no index needed)
for score in scores:
    print(score)

# index-based (when position matters)
for i in range(len(scores)):
    print(i, scores[i])
accumulator pattern  # initialize a running total to 0 before loop, add inside
Always initialize accumulator BEFORE the loop
total = total + value can also be written total += value
Works for sums, products, counts, building strings, building lists
total = 0
for i in range(1, 11):
    total = total + i
print(total)  # 55

# average from a list
total = 0
for num in numbers:
    total += num
average = total / len(numbers)
counter pattern  # count how many items meet a condition inside a loop
Initialize counter = 0 before loop
Inside loop: if condition: counter += 1
Can combine counter + total accumulators in one loop
even_count = 0
even_total = 0
for num in numbers:
    if num % 2 == 0:   # % 2 == 0 means EVEN
        even_count += 1
        even_total += num
filter / transform pattern  # build a new list from an old one, driven by a helper function
Filter: loop the source list, .append() only items that satisfy a condition — source is untouched
Transform: loop the source list, compute a new value each time, .append() the new value instead of the original
A helper function (e.g. is_hot(temp)) holds the condition/transform logic separate from the loop mechanics
Neither pattern mutates the source list — both build and return a brand-new one
def is_hot(temp):
    return temp >= 70

temperatures = [65, 72, 58, 81, 70]
hot_days = []
for temp in temperatures:
    if is_hot(temp):
        hot_days.append(temp)
print(hot_days)  # [72, 81, 70]
while condition:  # repeats while condition is True; use when repeat count is unknown
Pattern: initialize → test → update
Must update the condition variable inside the loop or it runs forever
while True: — intentional infinite loop; must use break to exit
# password checker
password = input("Password: ")
while password != "opensesame":
    print("Incorrect")
    password = input("Try again: ")
print("Access granted")
break  # exits the loop entirely — no more iterations
Works in both for and while loops
Only exits the innermost loop it's in
Common pattern: while True: ... if done: break
score = 0
while score != -1:
    score = int(input("Score (-1 to quit): "))
    if score == -1:
        break
    print("Recorded")
continue  # skips the rest of the current iteration and starts the next one
Loop does NOT exit — only this iteration is skipped
Useful to filter out items that don't meet a condition
In a while loop, make sure the update variable changes before continue or you get an infinite loop
for num in range(1, 11):
    if num % 2 != 0:
        continue       # skip odds
    print(num)         # only prints evens

🔤 Strings

string[index]  # get a single character by position — 0-based
First character is index 0, not 1
word[-1] — last character (negative counts from end)
word[-2] — second-to-last
word = "Python"
# + indexes:  0  1  2  3  4  5
# - indexes: -6 -5 -4 -3 -2 -1
word[0]   # "P"
word[2]   # "t"
word[-1]  # "n"  (last)
word[-2]  # "o"  (second-to-last)
string[start:stop]  # slice: get a substring — start included, stop excluded
word[1:4] on "Python" → "yth" (indexes 1, 2, 3)
word[:3] — from start up to index 3 (not included)
word[3:] — from index 3 to the end
word[:] — copy of the whole string
word[start:stop:step] — every Nth character
word[0:6:2] on "Python" → "Pto"  (every 2nd char)
word[::-1] → reversed: "nohtyP"
Negative slices: word[-3:] → last 3 chars;  word[:-2] → all but last 2
word = "Python"
word[1:4]    # "yth"
word[:3]     # "Pyt"
word[3:]     # "hon"
word[::-1]   # "nohtyP"  (reversed)
word[-3:]    # "hon"  (last 3 chars)
string.strip()  # removes leading and trailing whitespace; returns new string
" hello ".strip() → "hello"
Does NOT modify the original — assign the result
After strip(), empty result "" signals "no data / missing field"
name  = " Ron Hensley "
clean = name.strip()    # "Ron Hensley"

field = parts[1].strip()
if field == "":
    print("no data")
string.lower()   /   string.upper()  # returns new all-lowercase / all-uppercase string
"Hello".lower() → "hello"
"hello".upper() → "HELLO"
Use .lower() before comparisons for case-insensitive matching
answer = input("Yes or no? ").lower()
if answer == "yes":
    ...
string.replace(old, new)  # returns new string with ALL occurrences of old swapped for new
Case-sensitive: "Hello".replace("h", "J") → "Hello" (no change)
Replaces ALL occurrences, not just the first
Returns a new string — original is unchanged
msg   = "server down"
fixed = msg.replace("server", "database")
# "database down"
string.find(sub)  # returns index of first match, or -1 if not found (case-sensitive)
"hello".find("ll") → 2
"hello".find("z") → -1 (not found)
Case-sensitive: "URGENT".find("urgent") → -1
Use if text.find("x") != -1: or simpler: if "x" in text:
string.split(sep)  # splits string at separator, returns a list of pieces
"a,b,c".split(",") → ["a", "b", "c"]
"hello world".split(" ") → ["hello", "world"]
Result is a list — access pieces by index
record = "Ron,Hensley,ron@example.com"
parts = record.split(",")
first = parts[0]  # "Ron"
email = parts[2]  # "ron@example.com"
"sep".join(list)  # glues a list of strings together with separator between each item
", ".join(["a","b","c"]) → "a, b, c"
" | ".join(parts) → pipe-separated string
"".join(chars) → join with no separator
parts  = ["Ron", "Hensley", "ron@x.com"]
result = " | ".join(parts)
# "Ron | Hensley | ron@x.com"
method chaining  # call multiple string methods in a row — left to right
Each method returns a new string which the next method acts on
Order matters — strip first, then lower, then replace
text  = " URGENT: reset password "
clean = text.strip().lower().replace(": ", ":")
# "urgent:reset password"

📋 Lists

my_list = [a, b, c]  # create a list — ordered, mutable, any mix of types
Square brackets, comma-separated values
Can hold ints, floats, strings, bools — even mixed types
One variable holds many related values — better than score1, score2, score3…
list(range(start, stop)) — create list of integers from a range
scores = [10, 15, 8, 20]
names  = ["Alice", "Bob", "Carol"]
nums   = list(range(1, 6))  # [1, 2, 3, 4, 5]
len(list)  # returns the number of items in the list (also works on strings)
len([5, 6, 7, 8]) → 4
len("hello") → 5
Used in range(len(list)) for index-based loops
Valid indexes: 0 to len(list) - 1
list[index]  # access a single item by position — same 0-based rules as strings
scores[0] — first item
scores[-1] — last item
scores[2] — third item (index 2)
list[start:stop] — slice returns a new sub-list (same rules as strings)
items[:3] → first 3 items
items[2:] → from index 2 to end
items[:] → shallow copy of entire list
scores = [80, 95, 72, 88]
scores[0]    # 80
scores[-1]   # 88 (last)
scores[1:3]  # [95, 72]
list[index] = value  # replace an item in place — lists are mutable, strings are not
Changes the original list — no new list is created
"Mutable" means changeable in place
Strings are immutable — word[0] = "X" raises a TypeError
colors = ["red", "green", "blue"]
colors[1] = "yellow"
# ["red", "yellow", "blue"]
list.append(x)  # adds x to the END of the list; modifies in place, returns None
Adds exactly one item to the end
Does NOT return a new list — it changes the original
Most common list method; great for building lists one item at a time
trades = []
trades.append("AAPL")
trades.append("TSLA")
# trades = ["AAPL", "TSLA"]
list.insert(index, value)  # inserts value at position; everything after shifts right
First arg = where to insert; second arg = what to insert
list.insert(0, x) — insert at the very beginning
Modifies in place, returns None
nums = [10, 30, 40]
nums.insert(1, 20)
# [10, 20, 30, 40]
list.pop(index)  # removes AND returns the item at index; pop() with no arg removes the last
Only method that both removes AND gives you back the item
list.pop() — no arg → removes and returns the last item
removed = list.pop(2) — save the removed item in a variable
items = ["a", "b", "c"]
last = items.pop()    # "c" removed, last="c"
mid  = items.pop(0)  # "a" removed, mid="a"
# items is now ["b"]
list.remove(value)  # removes the FIRST matching value; raises ValueError if not found
Removes by value, not by index
Only removes the FIRST occurrence — not all matches
Raises ValueError if the value is not in the list
Does NOT return the removed item (returns None)
fruits = ["apple", "banana", "cherry", "banana"]
fruits.remove("banana")
# ["apple", "cherry", "banana"]  — first one removed
list.extend(other_list)  # adds ALL items from another list to the end, one by one
Unlike append, unpacks the other list — items added individually, not nested
Modifies in place, returns None
append([3,4]) adds [3,4] as a single nested element; extend([3,4]) adds 3 then 4 separately
nums = [1, 2]
nums.extend([3, 4])    # [1, 2, 3, 4]

nums2 = [1, 2]
nums2.append([3, 4])   # [1, 2, [3, 4]]  <-- nested!
list[:]  # shallow copy of a list — changes to the copy do not affect the original
copy = original[:] — creates a separate list
Changing copy[0] = 99 does NOT change original
copy = original without [:] makes BOTH point to the same list
numbers = [1, 2, 3]
backup  = numbers[:]
numbers[0] = 99
# numbers = [99, 2, 3]
# backup  = [1, 2, 3]  (unchanged)
grid[row][col]  # nested lists / 2D arrays — a list of lists, read and updated with two indices
Build with grid = [[...], [...], [...]] — outer index picks the row, inner index picks the column
Read a cell: grid[row][col] — update a cell in place: grid[row][col] = new_value
Only that one cell changes — the rest of the structure is untouched
grid[row] alone returns the entire inner list (the whole row)
Row-level operations like .pop()/.insert() on one inner list don't shift or affect any other row's indexes
board = [
    [" ", " ", " "],
    [" ", "X", " "],
    [" ", " ", " "]
]
board[0][2] = "O"   # top-right cell
board[2][1] = "X"   # bottom-middle cell
print(board[1][1])  # "X" -- center cell
list[:n]  # safe slicing — never raises IndexError, even past the list's length
my_list[:3] means "up to 3 items from the start" — returns fewer items if the list is shorter
No None padding, no error on short/empty lists — [][:3] just returns []
Direct indexing my_list[3] DOES raise IndexError when out of range — slicing is the safer choice for a variable-length prefix
def top_three(scores):
    return scores[:3]

top_three([100, 90, 80, 70])  # [100, 90, 80]
top_three([100])              # [100]
top_three([])                 # []

📚 Stacks, Queues & collections.deque

stack (LIFO)  # Last In, First Out — a plain list used with append()/pop()
Push: stack.append(item) — adds to the top (the end of the list)
Pop: stack.pop() — removes and returns the top item
Peek: stack[-1] — look at the top without removing it
Real-world models: a stack of dinner plates, undo history, the browser back button
Popping (or peeking) an empty stack raises IndexError — guard with if stack: first
history = []
history.append("page1")
history.append("page2")
history.append("page3")

last_page = history.pop()      # "page3" — most recently added comes off first

# guarded undo: pop only if there's something to pop
if history:
    print(history.pop())

# guarded DOUBLE undo — must check length, not just truthiness
if len(history) >= 2:
    history.pop()
    history.pop()
queue (FIFO) with a list  # First In, First Out — works, but pop(0) is slow on big lists
Enqueue: queue.append(item) — adds to the back of the line
Dequeue: queue.pop(0) — removes and returns the front item
Real-world models: a coffee-shop line, a printer queue
pop(0) is O(n): every remaining item has to shift left one slot — fine for small queues, slow at scale (see deque below)
def dequeue(q):
    if not q:
        return None          # underflow guard — nothing to remove
    return q.pop(0)

line = []
line.append("Ana")
line.append("Ben")
next_up = dequeue(line)   # "Ana" — first one in line is served first
collections.deque  # double-ended queue — O(1) append/pop from BOTH ends
Fixes the pop(0) slowness: .append() and .popleft() are both O(1), no shifting
.append(x) / .appendleft(x) — add to right / left end
.pop() / .popleft() — remove from right / left end
Import styles: import collections then collections.deque(), or from collections import deque then just deque()
from collections import deque

line = deque()
line.append("Ana")     # enqueue — O(1)
line.append("Ben")
next_up = line.popleft()  # "Ana" — dequeue, O(1), no shifting
mutable arguments & shared references  # mutating a list inside a function changes the caller's list too
Python passes objects by reference: a list argument and the caller's variable point at the SAME list in memory
Mutating it in place (.append(), .pop(), [i] =) is visible to the caller with no return needed
Reassigning the parameter (arr = []) does NOT affect the caller — that just points the local name at a new object
A shallow copy (list(x), x[:], x.copy()) copies the outer list, but if it holds mutable objects (lists/dicts), both copies still share THOSE inner objects — use copy.deepcopy() to fully separate them
def add_item(cart):
    cart.append("eggs")      # mutates the caller's list — no return needed

groceries = ["milk"]
add_item(groceries)
# groceries is now ["milk", "eggs"]

# shallow-copy hazard
teams = [["Ana"], ["Ben"]]
teams_copy = teams.copy()          # outer list is new...

⏱️ Big O & Algorithm Efficiency

Big O notation  # how work grows as input size (n) grows — not a literal timer
Describes the SHAPE of growth, not exact seconds — ignores machine speed, constants, and small-n details
O(1) constant — same number of steps no matter how big n is (e.g. dict lookup by key)
O(log n) logarithmic — each step cuts the remaining work about in half (e.g. binary search)
O(n) linear — work grows directly with n (e.g. scanning a whole list once)
O(n²) quadratic — work grows with n×n, typically a loop nested inside a loop (e.g. bubble/insertion sort)
Speed ranking for large n: O(1) < O(log n) < O(n) < O(n²)
See also the nested-loop antipattern entry under Nested Data Modeling for a worked O(n×m)→O(n) fix
O(n) vs O(log n) growth  # doubling n doubles linear work, but only adds ONE step to logarithmic work
List size 8 → 16 → 32 → 64 → 128 (doubling each time)
Linear steps (O(n)): 8, 16, 32, 64, 128 — scales right along with n
Logarithmic steps (O(log n)): ~3, ~4, ~5, ~6, ~7 — barely moves
Intuition: "guess my number 1-100" by halving the range each guess — ~7 guesses instead of up to 100
def halving_steps(n):
    # counts how many times n can be cut in half before reaching 1
    steps = 0
    while n > 1:
        n = n // 2
        steps += 1
    return steps

for size in [8, 16, 32, 64, 128, 1024]:
    print(size, halving_steps(size))
# 8 3 / 16 4 / 32 5 / 64 6 / 128 7 / 1024 10

🔍 Searching Algorithms

linear search  # check items one by one — works on ANY list, sorted or not — O(n)
Walks the list left to right, comparing each item to the target
Returns the index on a match, or a sentinel (commonly -1) if the target isn't found
Worst case checks every item — O(n) — happens when the target is last or absent
This is the same underlying scan that in and list.index() do internally
def linear_search(lst, target):
    for index, value in enumerate(lst):
        if value == target:
            return index
    return -1          # not found

linear_search([4, 9, 2, 7, 5], 7)   # 3
linear_search([4, 9, 2, 7, 5], 10)  # -1
binary search  # halve the search space each step — REQUIRES a sorted list — O(log n)
Tracks low and high index bounds; checks the midpoint and eliminates half the remaining range each step
If lst[mid] < target, the target must be to the right → move low up; if greater, move high down
Only works correctly on a SORTED list — on unsorted data, eliminating "half" can throw away the actual target
32 items → ~5 checks; 1,000,000 items → ~20 checks — the O(log n) payoff grows huge on large data
def binary_search(lst, target):
    low, high = 0, len(lst) - 1
    while low <= high:
        mid = (low + high) // 2
        if lst[mid] == target:
            return mid
        elif lst[mid] < target:
            low = mid + 1       # target is in the right half
        else:
            high = mid - 1      # target is in the left half
    return -1              # not found

binary_search([3, 7, 15, 22, 31, 45, 58], 31)  # 4
linear vs binary — which to use  # two questions decide it
"Is the data sorted?" — unsorted → linear search (sorting just for one search costs more than it saves)
"Am I searching once, or many times?" — a big sorted collection searched repeatedly (like a million user IDs looked up many times per second) → binary search wins overall
Small, one-off, or unsorted → linear search is simplest and fine

list.sort() — ascending (smallest first)

.sort() → changes original, returns None
sorted() → original unchanged, returns new sorted list
Decision rule: "Do I want to change this list?" → use .sort()
Decision rule: "Do I want a sorted copy?" → use sorted()
Both are stable: tied items keep their original relative order

# sorted() — new list, original untouched

bubble sort  # repeatedly swap out-of-order neighbors — O(n²), rarely used in real code
Compare each pair of neighbors; swap them if they're out of order
Repeat passes over the list until a full pass makes no swaps — the list is sorted
Big values "bubble" toward the end one swap at a time
O(n²) worst case: nested passes over the whole list, no shortcuts
def bubble_sort(lst):
    arr = lst.copy()
    for pass_num in range(len(arr) - 1):
        for i in range(len(arr) - 1 - pass_num):
            if arr[i] > arr[i + 1]:
                arr[i], arr[i + 1] = arr[i + 1], arr[i]   # swap neighbors
    return arr

bubble_sort([5, 2, 4, 1])   # [1, 2, 4, 5]
insertion sort  # grow a sorted left side one element at a time — O(n²) avg, close to O(n) on nearly-sorted data
Mental model: sorting a hand of playing cards — take the next card, slide it into place among the cards already sorted to its left
For each element: store it as key, shift every larger element to its left one slot right, then drop key into the gap
Random/jumbled data → lots of shifting → ~O(n²)
Nearly-sorted data → almost no shifting → close to O(n) — this is where it beats bubble sort
def insertion_sort(lst):
    arr = lst.copy()
    for i in range(1, len(arr)):
        key = arr[i]
        pos = i - 1
        while pos >= 0 and arr[pos] > key:
            arr[pos + 1] = arr[pos]     # shift bigger element right
            pos -= 1
        arr[pos + 1] = key              # drop key into the gap
    return arr

insertion_sort([5, 2, 4, 6, 1, 3])   # [1, 2, 3, 4, 5, 6]
why use sorted()/.sort() instead of hand-rolled sorts  # built-in Timsort is O(n log n) — much faster than bubble/insertion's O(n²)
Python's built-in sorted()/.sort() use Timsort, running in about O(n log n)
Bubble sort and insertion sort are both O(n²) — fine for tiny lists, much slower once a list grows past ~30 items
Rule of thumb: in real code, reach for sorted()/.sort() — write bubble/insertion sort only to learn how sorting works

list of dicts  # models a table of records — each element is a dict with the same keys

"Loop outside, helper does one item" — the for statement stays in the caller; the helper is called once per iteration

🚧 Exception Handling

try:   except SomeError:  # catch a runtime error and recover instead of crashing
try: holds code that might fail; except SomeError: runs only if that specific error is raised inside the try block
Commonly wraps int()/float() conversions of user input, since bad input raises ValueError
Catch a specific type (except ValueError:) or a bare except: to catch anything
Often combined with a loop so the user is re-prompted until valid input is given
A variable assigned inside try may not exist afterward if the error happened before that line ran — give it a fallback value inside except
while True:
    try:
        price = float(input("Please enter a price: $"))
        break
    except ValueError:
        print("Invalid input. Please enter a numeric value.")
multiple except clauses  # stack several except blocks under one try, one per error type
Python checks each except in order and runs only the FIRST one that matches
Once one except block runs, the rest are skipped — not evaluated as separate independent checks
Each except clause needs the same indentation, lined up under try
try:
    num = int(input("Enter a number: "))
except ValueError:
    print("Please enter a valid number.")
except NameError:
    print("This branch won't run from bad input here.")
try: except: else: finally:  # else runs only on success, finally ALWAYS runs
Full structure: try: → except: → else: → finally:
else is a good place for code that should run only when the risky line succeeded
finally runs whether the try block succeeded, failed and was caught, or failed and was NOT caught — useful for cleanup
def safe_int():
    try:
        value = int(input("Enter a number: "))
    except ValueError:
        print("That wasn't a valid number!")
    else:
        print("You entered:", value)
    finally:
        print("Done processing input.")
try-block scope  # except only catches errors on lines actually indented under try
If a variable is only assigned inside try and that line fails, the variable never gets created
Using that variable in a LATER line outside the try/except can raise NameError, and no except block will catch it — that line isn't "inside" the protected region
Fix: either include the risky use inside the same try, or assign a fallback value inside except so the variable always exists afterward

    num = int(input("Enter a number: "))

A function that only prints cannot have its result stored, tested, or passed to another function

the "four pillars" spec method  # name Inputs, Outputs, Constraints, Edge cases before writing any code
Inputs — what data the function needs to receive
Outputs — what it returns or displays
Constraints — rules the valid input must satisfy, e.g. "list must have at least 2 prices"

Invalid-input example: amount not being a number, or the input list being None instead of a list — guarded against rather than computed on

[expr for item in iterable if cond]  # list comprehension — builds a new list in one line
Basic form: [expr for item in iterable]
With filter: [expr for item in iterable if condition]
Equivalent to a for-loop that appends to a list, but shorter and returns the list directly
Can nest: [expr for x in outer for y in inner]

Same syntax as list comprehension but with {} instead of []
Automatically de-duplicates results, like any set
Useful for collecting unique values derived from a collection

Needs both a key expression and a value expression, separated by :
Can transform an existing dict's keys/values, or build one from a list

(expr for item in iterable if cond)  # generator expression — like a list comprehension but lazy
Uses () instead of []
Values are computed on demand as you iterate — nothing is stored up front
Can only be iterated once; after it's exhausted, it's empty
Use when you only need to loop over the results once and the source could be large (saves memory)
Pass directly into functions that accept an iterable, no extra parentheses needed: sum(n * n for n in range(10))

value_if_true if condition else value_if_false  # conditional expression — a one-line if/else that produces a value ("ternary")
Not a statement — it's an expression that evaluates to a value, so it can be assigned or embedded
Reads left to right: the "true" result comes first, then the condition, then the "false" result
Great inside comprehensions and f-strings; avoid chaining more than one — nested ternaries get unreadable fast

# inside a list comprehension

# ["even", "odd", "even", "odd", "even"]

# inside an f-string
print(f"You are {'eligible' if age >= 18 else 'not eligible'} to vote")
(name := expr)  # assignment expression — the "walrus operator": assigns AND produces a value in one expression
Syntax is name := expr, always the colon-equals — different from plain =, which is a statement and can't appear inside an expression
Almost always needs its own parentheses when used inside a larger expression: (n := len(data))
Classic use: avoid calling the same expensive function/expression twice — once to check it, once to use it
Very common in while loops that read/compute something and test it in the same breath
Common in comprehensions: filter on a computed value AND keep that computed value, without recomputing it
Doesn't replace regular = for normal top-level assignment — it's for "I need to assign AND use the value in the same expression"
# without walrus — has to call input() twice or use an extra line

    print(f"You typed: {line}")
    line = input("Enter text (blank to quit): ")

# with walrus — assign and test in one line
while (line := input("Enter text (blank to quit): ")) != "":
    print(f"You typed: {line}")

# avoiding a duplicate/expensive call in an if
data = [1, 2, 3, 4, 5]
if (n := len(data)) > 3:
    print(f"List is long: {n} items")

# inside a comprehension — compute once, filter and reuse the same value
results = [y for x in range(10) if (y := x ** 2) > 20]
# [25, 36, 49, 64, 81]  — x**2 isn't computed twice per item

class MNQPosition:
    def __init__(self, symbol, entry_price, current_price, quantity):
        self.symbol = symbol
        self.entry_price = float(entry_price)
        self.current_price = float(current_price)
        self.quantity = int(quantity)
        self.multiplier = 2.0  # $2 per point for Micro E-mini Nasdaq (MNQ)

    def get_unrealized_pnl(self) -> float:
        return (self.current_price - self.entry_price) * self.multiplier * self.quantity

    def __init__(self, account_id, initial_cash):

        self.cash = float(initial_cash)
        self.positions = []  # 1-to-Many relationship

        self.positions.append(pos)

    def get_net_equity(self) -> float:
        total_pnl = sum(pos.get_unrealized_pnl() for pos in self.positions)
        return self.cash + total_pnl

Pillar 1: Encapsulation & Accessor Methods  # protecting internal state with getters, setters & boundaries
Encapsulation: Bundling data and behavior together while restricting direct access to raw internal state

class ShelterPet:

        return self._health

Pillar 2: Inheritance ("Is-A") & Method Overriding  # class Child(Parent): code reuse and specialization
Inheritance: Establishes an "Is-A" hierarchy where subclasses acquire attributes and behaviors from a base class

Method Overriding: Redefines a parent method in the subclass to provide specialized child behavior
class Point3d:
    def __init__(self, x: float, y: float, z: float):
        self._x = x
        self._y = y
        self._z = z

    def move(self, dx, dy, dz):
        self._x += dx
        self._y += dy
        self._z += dz

    def __init__(self, x, y, z, color: str):
        super().__init__(x, y, z)  # initialize parent Point3d
        self._color = color

    def set_color(self, color):
        self._color = color

    def __str__(self):
        return f"ColoredPixel(x={self._x}, y={self._y}, z={self._z}, color={self._color})"

Pillar 3: Composition ("Has-A") & Cascaded Delegation  # assembling complex systems from modular components
Composition: A design pattern where an object contains instances of other classes ("Has-A" relationship)
Modularity: "Prefer composition over inheritance" — promotes flexible toolbelts over rigid family trees
Cascaded Delegation: Calling a method on a composite object automatically delegates work down to its constituent components
class Line3d:
    # A 3D line segment composed of two Point3d objects
    def __init__(self, start: Point3d, end: Point3d):
        self._start = Point3d(start.get_x(), start.get_y(), start.get_z())
        self._end   = Point3d(end.get_x(),   end.get_y(),   end.get_z())

    def move(self, dx, dy, dz):
        # Cascaded delegation: translates both underlying endpoints
        self._start.move(dx, dy, dz)
        self._end.move(dx, dy, dz)

class Plane3d:
    # A 3D plane composite composed of 4 Line3d objects
    def __init__(self, l1: Line3d, l2: Line3d, l3: Line3d, l4: Line3d):
        self._lines = [l1, l2, l3, l4]

    def move(self, dx, dy, dz):
        # Cascaded delegation: plane move delegates to all 4 lines -> each line delegates to 2 points!
        for line in self._lines:
            line.move(dx, dy, dz)

Polymorphism ("Many forms"): Calling the exact same method identifier (e.g. .render(), .attack_power()) across a collection of different object types

Duck Typing: "If it walks like a duck and quacks like a duck, it's a duck" — Python cares about available methods, not explicit class inheritance
